# 架构选型的判断力

工具箱满了。前三卷往里面放了足够多的东西——大模型的原理、Agent 的执行机制、MCP 和 Skill 的扩展方式、多 Agent 的协作模式、记忆体系、上下文工程、知识注入的三条路。但工具箱满不等于你知道该用哪个。一个团队为了自动格式化代码，搭了一套多 Agent + MCP + RAG 的系统，花了两周，跑一次 30 秒消耗 50K Token——而同样的事情一个 `gofmt` 命令 0.1 秒就能搞定。这不是虚构的故事，这是"有了锤子看什么都像钉子"的典型症状。真正的判断力不是"知道有哪些工具"，而是"知道什么时候用什么工具，什么时候不用"。这一卷要建立的就是这种判断力。第一步是选型决策——直接对话还是 Agent？单 Agent 还是多 Agent？MCP、Skill、SubAgent 各自的甜蜜区和雷区在哪里？什么时候该组合使用，什么时候一个都不需要？每一个选择都有明确的判断标准，而不是"越高级越好"。第二步是规范驱动——当你决定了用什么架构，怎么让 AI 稳定地产出符合预期的结果？答案不是写更好的提示词，而是建立可版本化、可验证、可复用的规范体系，把"手艺活"变成"工程实践"。贯穿这两章的核心原则只有一个：从最简单的方案开始，每增加一个组件都要问"它解决了什么问题、引入了什么代价"，选择"刚好够用"的方案而不是"最先进"的方案。
