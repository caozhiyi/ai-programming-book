# 工程化与未来

前四卷讨论的都是"怎么让 AI 系统做对事"——理解模型、设计 Agent、管理上下文、选对架构。但一个能"做对事"的系统，离上生产还差最后一道关：它能不能被工程化地运行、治理和演进？这一卷从五个维度回答这个问题。首先是全景视图——把前十二章讨论过的所有零件钉在一张系统蓝图上，画出从用户请求到代码交付的完整链路，让你看清每个组件的位置和连接关系。然后是安全——AI 系统面临的威胁和传统软件截然不同，Prompt Injection 利用的不是代码漏洞，而是大模型无法区分"指令"和"数据"这个架构层面的根本特征，你需要的不是修补某个漏洞，而是建立多层防御体系。安全之外是非确定性带来的工程挑战——同样的输入，模型可能给出不同的输出，传统的单元测试、断言、回归测试都建立在"确定性"假设上，当这个假设不再成立，你需要用评估替代断言，用可观测性替代代码审查，用渐进式迁移替代一次性发布。接下来是组织治理——当 AI 编程从个人工具变成团队基础设施，谁来维护 Prompt 和 Skill？模型升级怎么管理？AI 资产的技术债怎么偿还？这些问题不解决，系统会在三个月内静默腐烂。最后，当所有工程化问题都有了答案，还剩一个更大的问题：AI 编程的边界在哪里？它会往哪里演进？程序员的角色会怎么变？这不是畅想，而是基于前面所有章节建立的认知体系做出的推演——每一个判断都有逻辑支撑，每一个前瞻都锚定在原理之上。
